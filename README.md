## 核心概念速查

| 概念 | 作用 |
| --- | --- |
| Task | 可被调度执行的基本程序单元 |
| Scheduler | 根据任务状态和优先级选择运行任务 |
| Priority | 表示任务调度优先级 |
| Ready state | 任务可以运行并等待调度 |
| Blocked state | 任务等待时间、队列、信号量或其他事件 |
| Suspended state | 任务被显式挂起，不参与正常调度 |
| Queue | 在任务或中断之间传递数据 |
| Binary semaphore | 用于事件同步或简单资源协调 |
| Counting semaphore | 用于计数型资源管理 |
| Mutex | 用于保护共享资源并支持优先级继承 |
| Event group | 使用多个事件位表达和等待组合条件 |
| Task notification | 面向特定任务的轻量级通知机制 |
| Software timer | 由定时器服务任务管理的软件定时器 |
| Tickless | 在系统空闲时减少系统节拍以降低功耗 |
| Heap scheme | FreeRTOS 动态内存管理算法 |

## 任务通信方式对比

| 机制 | 主要用途 | 典型特点 |
| --- | --- | --- |
| 消息队列 | 传递结构化数据或消息 | 支持多个消息，适合生产者与消费者 |
| 二值信号量 | 事件同步 | 只有可用和不可用两种状态 |
| 计数型信号量 | 资源计数或事件计数 | 可表示多个资源或累计事件 |
| 互斥信号量 | 保护共享资源 | 支持优先级继承 |
| 队列集 | 同时等待多个通信对象 | 将多个队列或信号量统一管理 |
| 事件标志组 | 等待多个条件 | 通过事件位组合系统状态 |
| 任务通知 | 单任务定向通知 | 开销小、速度快、使用范围明确 |

## 动态与静态创建

| 方式 | 特点 | 适用场景 |
| --- | --- | --- |
| 动态创建 | 从 FreeRTOS 堆中申请任务控制块和任务栈 | 任务数量或生命周期需要灵活变化 |
| 静态创建 | 由应用程序提供任务控制块和任务栈 | 需要确定性内存、避免运行时分配 |

实际工程中应根据内存策略、任务生命周期、实时性和故障恢复要求进行选择。

## 学习建议

1. 先理解任务状态、优先级和调度器，再开始学习通信机制。
2. 先用动态方法完成任务实验，再用静态方法比较内存管理差异。
3. 学习每个 API 时同时记录调用环境、阻塞行为、超时参数和中断可用性。
4. 先掌握队列、二值信号量和互斥量，再学习队列集、事件组和任务通知。
5. 使用任务状态查询和运行时间统计定位调度、阻塞和优先级问题。
6. 学习低功耗和内存管理时，结合芯片 RAM、系统节拍和任务生命周期进行分析。
